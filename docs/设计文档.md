# 模型控制台（astrbot_plugin_model_panel）

> 本文档是项目的核心上下文，任何 AI / 开发者打开本仓库都应先读此文档，避免重复调研。
> 记录：本插件的需求、技术结论、依赖的 AstrBot 核心 API、以及已确认的实现方案。

## 一、定位

一个独立的 **AstrBot 模型管理与检测插件**，通过自带 WebUI（模型控制台）统一完成：模型延迟/存活检测、排序、默认模型查看、伴侣插件精准模型一键批量替换，以及检测历史的持久化与统计。

- 插件目录 / 包名：`astrbot_plugin_model_panel`
- 展示名：**模型控制台**
- WebUI：Vue3 + Naive UI + Vite + vue-i18n，hash 路由，作为 AstrBot 面板页面展示（非弹窗）

## 二、功能需求

1. **控制台**：全局总览 + 最近一次检测的存活率 + 累计检测条数。
2. **模型检测排序**：
   - 读取全局 LLM（chat）模型，按供应商分组展示
   - 延迟检测 + 存活检测，支持重试
   - 排序功能
   - 单独检测 / 一键检测
   - 一键检测采用「启动 + 轮询」异步任务，逐模型返回结果实时刷新
   - 检测开关：关闭后"一键检测"跳过该模型
   - 状态持久化：检测结果、勾选状态、上次摘要写入 localStorage
   - 结果列独立展示：按归一化错误码（成功 / 超时 / 失联 / 拒绝连接 / 鉴权失败 / 请求受限 / 模型不存在 / 服务异常 / 已跳过）展示，禁止显示接口返回的整段堆栈
3. **默认模型切换**：只读展示 AstrBot 当前默认模型（写入能力后续再做）。
4. **伴侣插件模型替换**（最核心）：
   - 读取伴侣插件（astrbot_plugin_private_companion）的精准模型配置
   - 一键批量替换模型（把精准配置里已使用的模型批量换成新模型）
   - 未选择替换的保持原样
   - 展示配置模式 / 已配置数量 / 未配置项
5. **历史存储**：检测历史以 SQLite（WAL 模式）持久化到 AstrBot 数据目录，跨重启保留；超过保留天数自动清理。
6. **主题与多语言**：
   - 深 / 浅主题切换，localStorage 持久化
   - 中 / 英 / 日 / 韩四语切换，默认中文
7. **插件模型（全插件模型配置扫描，v1.2.6）**：
   - 自动发现所有已安装插件配置里的模型项，列出来可单项更换 / 批量替换
   - 三级识别（逐条标注可信度）：schema `_special` 声明（high）、值命中已加载
     provider id / 模型名（high/medium）、键名提示（low，可一键隐藏）
   - 镜像配置（顶层扁平副本 + 分组嵌套，陪伴插件即此结构）自动合并 + 写回同步
   - 支持 JSON 字符串映射内层（如 `model_fallback_overrides`）的读取与写回

## 三、技术方案（基于 AstrBot 4.27.4 源码确认）

AstrBot 核心源码位置（调研时）：`_References\AstrBot`（版本 4.27.4）。
注意：`_References\AstrBot-master` 是旧版 4.26.6，勿混淆。

### 后端（Python, AstrBot Star 插件）

- 继承 `Star`，`context.register_web_api(...)` 注册 Web API
- **获取 chat 模型**：`context.get_all_providers()` → `list[Provider]`
- **延迟/存活检测**：`await provider.test(timeout=45)`；失败可按 `_conf_schema` 配置重试
- **错误归一化**：关键字匹配映射到 `error_code`（timeout/connect/refused/auth/rate_limit/not_found/server/unknown）；原始消息截断到 80 字符
- **AstrBot 默认模型（只读）**：`context.provider_manager.provider_settings["default_provider_id"]`
- **读伴侣插件 providers**：`context.get_registered_star("astrbot_plugin_private_companion").config`
  - `StarMetadata.config` 是 `AstrBotConfig`（dict 子类，有 `save_config()`）
  - 伴侣插件 providers 直接存在插件配置里（key 如 `FAST_RESPONSE_PROVIDER_ID` 等，见伴侣插件 `_allowed_provider_keys()`）
  - 写：改 `config[key]` 后 `config.save_config()`（零侵入，不改伴侣插件代码）
- **保存插件自身配置**：`AstrBotConfig` 支持 `config[key]=...` + `save_config()`
- **数据库**：`aiosqlite` + WAL（`journal_mode=WAL, synchronous=NORMAL`）
  - 文件位于 `<AstrBot data_dir>/model_panel.db`
  - 表 `test_sessions`、`model_test_results`，带索引

#### 异步一键检测

AstrBot 插件 Page 桥接层只支持 JSON 同步调用，无法直接 SSE 推送。采用「启动 + 轮询」：

- `POST /panel/providers/test_all_stream` 立即创建会话 + 后台 `asyncio.create_task` 跑检测
- 内存 `SessionManager` 维护每个 session 的 `items: list`，每完成一个模型就 `append_item`
- `GET /panel/providers/session/{id}` 返回当前 `items` 快照与 `done` 标志
- 前端以 600ms 间隔轮询；任务完成由 `done=true` 触发

这样既能给前端"边跑边显示"的体验，又能稳定运行。

### WebUI（Vue3 + Naive UI + Vite + vue-i18n）

- 构建参考：comfyui-anima 的 `webui-src/vite.config.ts`
- **必须**：`base: "./"`、`inlineDynamicImports: true`、`cssCodeSplit: false`（单文件产物）
  - 原因：AstrBot 插件页面只对入口 index.html 直接引用的资源重写 asset_token；跨 chunk import 在旧版会 401 白屏。单文件产物最稳。
- 路由用 `createWebHashHistory`（hash 路由，无需 SPA fallback）
- 产物输出到 `pages/model-panel/`（metadata.yaml 的 pages 注册）
- Naive UI 主题：darkTheme / lightTheme；`data-theme` 写入 `<html>` 让 CSS 变量同步
- 国际化：`vue-i18n` legacy: false；locales 在 `webui-src/src/locales/`

### 插件配置文件

- `metadata.yaml`：name、display_name、version、author、pages（注册模型控制台页面）
- `_conf_schema.json`：暴露 AstrBot 配置 UI 字段
- 用 `@register` 装饰器或 metadata 注册

## 八、全插件模型配置扫描（v1.2.6，模块 `plugin_models.py`）

### 需求

换模型时不该只盯着陪伴插件：视觉模型、TTS、向量模型等往往散落在各个插件自己的配置里，
人工去每个插件的配置页翻找既慢又容易漏。所以需要一个「全插件」视图：
把配置里的模型项都列出来，能就地更换、也能批量「旧模型 → 新模型」。

### 识别规则（三级，前端逐条标注可信度）

| 级别 | 来源 | 判据 | 可信度 |
| --- | --- | --- | --- |
| 1 | schema 声明 | `_conf_schema.json` 里 `_special` 为 `select_provider` / `select_provider_tts` / `select_provider_stt` | high |
| 2 | 值命中 | 字符串值等于某个已加载 provider 的 id（high）/ 模型名（medium）；含 JSON 映射展开 | high / medium |
| 3 | 键名提示 | 键名含 `provider` / `model` 且值是非空短字符串，但既不是已知 id 也不是已知模型名 | low（前端**默认不显示**） |

### provider 目录覆盖范围（v1.2.7）

命中判定与「更换为」下拉都基于 `provider_catalog()`，必须覆盖 AstrBot 支持的**全部**
provider 类型，少一类就会出现「插件里配了这类模型却被标成未匹配、下拉里也选不到」：

| 类型 | 来源 |
| --- | --- |
| chat | `context.get_all_providers()` |
| tts | `context.get_all_tts_providers()` |
| stt | `context.get_all_stt_providers()` |
| embedding | `context.get_all_embedding_providers()` |
| rerank | **Context 没有 getter**（4.27.4），直接取 `provider_manager.rerank_provider_insts` |

另外标 `is_default`：chat 取 `provider_settings.default_provider_id` 与
`provider_manager.default_chat_provider_id`，tts / stt 取对应的
`provider_*_settings.provider_id`；embedding / rerank 在主配置里没有全局默认项
（由使用它们的插件各自指定），故不标。

关键实现点：

- **schema 拍平**：`object` 分组递归进 `items`，`template_list` 用 `None` 占位索引，
  读取时再按实际列表长度展开成具体路径（`template_list_demo[0].provider_id`）。
- **值命中优先**：不做「先看键名」的过滤，避免漏掉「插件自己起的字段名」。
- **JSON 映射展开**：如陪伴插件 `model_fallback_overrides = '{"KEY":"provider_id"}'`，
  展开成多条内层条目，写回时读出 → 改内层 → 重新序列化。
  内层**只信值命中**，不做键名提示：`task_prompt_overrides` 的内层键名同样带 provider，
  靠键名猜会把提示词正文当成模型。
- **误报防护**：schema 带 `options` 的枚举项、非字符串类型不参与键名提示
  （否则 `provider_config_mode=quick` 会被当模型）；`__` 前缀的 AstrBot 内部字段
  （`__template_key`）直接跳过。
- **template_list 内的字段不做键名提示**（v1.2.7）：模板条目是用户自定义的列表项，
  里面的 `model_name` / `base_model` 属于插件自己的业务（comfyui-anima 的 LoRA 文件名、
  工作流底模），不是 AstrBot provider。这类字段只认 schema `_special` 与值命中。
  判定用 `_is_template_field()`，同时兼容具体路径（`loras.0.model_name`）与
  schema 占位路径（`loras.None.model_name`）。
- **镜像去重**：同一 key 同时出现在顶层扁平副本与分组嵌套（陪伴插件的历史结构）时，
  值相同只保留最深的一条并标 `mirrored`，值不同则两条都列并标 `conflict`。
- **空值也列（v1.2.9）**：schema `_special` 声明的项是插件官方定义的"模型配置入口"
  （如 comfyui-anima 的 `translate_llm_model` / `llm_model`），**没填值时也列出**并标
  `configured=false`，前端显示「未配置」、可直接配置。教训：v1.2.6 一开始把"只列非空值"
  无差别套到所有来源上，导致这些**空入口整条消失**，用户以为插件漏识别了。
  值命中 / 键名提示两类仍然只收非空值（它们本来就有值）。
  前端对应开关「显示未配置项」（默认开启）；分组头部显示「x 已配置 · y 未配置」。
- **条目排序**：同一插件内"已配置在前、未配置沉底"（stable，保持各自相对顺序）。
- **插件级统计**：`special_slots` / `special_configured` / `special_unconfigured`，
  用于一眼判断"这个插件的模型是没配，还是没被识别到"。

### 写回语义

- 通用：按 `path` 精确写回（dict 键 / list 下标 / JSON 映射内层），
  写前校验「原值必须是字符串」且路径有效，失败只报错不改；
  改动按插件聚合后各 `save_config()` 一次。
- 陪伴插件特例：key 同时存在顶层扁平副本与 `model_assignment_config` 分组，
  必须走 main.py 的 `_flat_set`（全量同步）语义，否则插件读到的仍是旧值。
- 运行时同步（尽力而为）：插件实例属性名 == 配置键名、且属性当前值 == 我们看到的旧值时
  才 `setattr`。很多插件在 bootstrap 时把配置读进实例属性、之后不再读 config，
  这类插件改完需要重载；前端会提示。

> 重要事实（AstrBot 4.27.4 `star_manager`）：`StarMetadata.config` 与插件实例
> `self.config` 是**同一个 `AstrBotConfig` 对象**，所以改 `star.config` + `save_config()`
> 对插件是即时可见的。

- `POST /panel/plugin_models/set` → `{items:[{plugin, path, value, container?}]}`

## 九、隐藏指令 `/陪伴分数` 的数据来源（v1.2.8）

指令是无副作用的**只读**查询（不写伴侣插件任何状态），数据全部取自伴侣插件
`star_cls.data["users"][<sender>]`。

伴侣插件有两个容易混淆的维度，指令里分两行展示：

| 维度 | 字段 | 取值 | 含义 |
| --- | --- | --- | --- |
| 长期关系阶段 | `relationship_score` | 八阶段：极度疏离 / 强烈疏离 / 疏离 / 初识 / 熟悉 / 亲近 / 亲密 / 深度联结 | 由关系账本长期累积，只在分数越档时变化 |
| 当前互动状态 | `current_interaction` | 七档：回避 / 受伤 / 放松 / 活泼 / 温暖 / 亲近 / 爱意 | 短期互动温度，受边界、被刺到、重新接近等事件影响，可有有效期 |

核对过的事实（伴侣插件 2.x）：

- 阶段边界与 `relationship_policy._DEFAULT_STAGES` 一致，本插件 `_AFFINITY_STAGES`
  与之一一对应（1200 / 900 / 600 / 200 / 0 / -400 / -800）。
- 互动档位 key 与中文标签来自 `companion_interaction_expression.ExpressionBand` /
  `EXPRESSION_BAND_LABELS`；投影函数 `current_interaction_projection()` 的归一化语义：
  普通用户不允许「亲近 / 爱意」（降到温暖，reason `owner_role_required`）、
  不得超过 `normal_interaction_band_cap`（默认 `warm`）、
  `expires_at` 过期且无动态余波时回到 `relaxed`。
- 档案里没有 `current_interaction` 时，用 `_baseline_band()` 规则按分数推算：
  `owner_exclusive` → 亲近；`<-400` → 回避；`<0` → 受伤；`>=600` → 温暖；
  `>=200` → 活泼；否则放松。指令会标注「按好感度推算」，避免把基线当成真实状态。
- 档位键名历史上的写法不统一，读取时依次尝试
  `expression_band` / `band` / `state` / `mode`，并兼容只写中文 `label` 的档案。

> 为什么不在指令里 import 伴侣插件的模块：版本间文件位置与命名都可能变，
> 一旦 import 失败指令就整个不可用。这里采用"读数据 + 复刻规则"的方式，
> 只用稳定的持久化字段，伴侣插件升级不会打断指令。
