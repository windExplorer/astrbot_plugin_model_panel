# 🌸 萌萌模型控制台（astrbot_plugin_model_panel）

AstrBot 的模型运维面板：**检测、监控、计费、切换**，一个插件管完。

> 本插件主要为个人使用而开发，围绕自己的实际需求打磨，非通用产品。介意勿用，欢迎 fork 自改。

## 它解决什么问题

用 AstrBot 跑「我会永远陪着你」陪伴插件时，想换个模型得去后台逐个改 provider 配置。
这个插件把这件事搬到了两个地方：

- **WebUI 面板**：一键检测所有模型的延迟与存活、批量替换模型、记账（花费估算）；
- **聊天指令**：发 `/模型状态` 看健康、`/模型检测` 真打一遍、`/切换系统模型` 回个序号就换模型。

陪伴插件地址：https://github.com/menglimi/astrbot_plugin_private_companion

## 安装

- **插件市场**：AstrBot 插件市场搜「萌萌模型控制台」；
- **压缩包**：下载 Release 中的 zip，在插件管理页上传安装。

**前置条件：管理员 ID**。除 `/陪伴分数` 外所有指令、以及所有告警投递，都依赖
AstrBot 的「管理员 ID」列表（**WebUI → 平台配置 → 管理员 ID**，填真实 QQ 号）。
默认值 `astrbot` 是占位符，插件会主动跳过它——不填的话指令会被判无权限、告警一条也收不到
（未送达的告警保持待补发，下一轮重试，超 24 小时放弃）。

## 聊天指令

群聊需要 @机器人（或按你配置的前缀唤醒）。发 **`/模型帮助`** 可以在聊天里直接看这张表（卡片版）。

| 指令 | 权限 | 花额度 | 说明 |
| --- | --- | --- | --- |
| `/模型状态` | 管理员 | ❌ | 总览卡：分组 + 序号 + 延迟 / 成功率，只读、不挂选单 |
| `/模型统计 [关键词]` | 管理员 | ❌ | 单模型明细：首字 / P95 / 整轮 / 失败次数；回序号看明细 |
| `/模型检测 [关键词…]` | 管理员 | ✅ | 真实探测所选模型并更新面板数据；回序号可多选（一次最多 30 个） |
| `/全部模型检测` | 管理员 | ✅ | 不挑通道，加载中的对话模型全测一遍 |
| `/切换系统模型 [关键词]` | 管理员 | ❌ | 回序号改 AstrBot 默认对话模型，切换成功回一张结果卡 |
| `/模型静音 [开\|关\|状态]` | 管理员 | ❌ | 全部模型告警推送的总开关 |
| `/模型帮助` | 管理员 | ❌ | 指令速查卡（就是上面这张表） |
| `/陪伴分数` | 全员 | ❌ | 查自己在陪伴插件里的好感度与互动状态 |

> `/模型检测` 的旧名 **`/检测模型` 仍可用**（注册成了别名），老习惯不用改。

几个口径要知道：

- `/模型状态`、`/模型统计`、`/模型检测` 操作的都是**「指令检测」通道**那份名单
  （模型管理页里逐个勾选）；`/切换系统模型` 例外，它列全部有效对话模型——换模型是全量决策；
- **回序号**只认「整条消息就是数字和分隔符」、只认**列出选单的那个人**，
  选单 3 分钟有效、取一次即作废，越界不作废可重输。日常的数字消息照常走 LLM，不会被吞；
- 检测**共用一把全局锁**（手动 / 定时 / 指令 / 联动都一样），已有检测在跑时会礼貌拒绝，不排队；
- 检测结果都会**喂进状态机与告警链路**：刚测出的故障立刻反映到面板与告警，不用等下一轮巡检。

## 卡片

所有指令共用同一张卡（`card_render.render_card`），骨架与
[萌萌权限控制台](https://github.com/windExplorer/astrbot_plugin_user_gateway) 的「切换模型」一致：

```
╭──────────────────────────────────────────────────────╮
│ 模型状态                                        ╭──╮ │   ← 头：渐变底、大字结论、汇总图例
│ 12 个模型 · 正常 9 / 故障 2                     │只读│ │
├──────────────────────────────────────────────────────┤
│                              延迟          成功率     │
│ ╭──────────────────────────────────────────────────╮ │
│ │ ① OpenAI · 3 个模型                              │ │   ← 分组行与模型行共用一个序号空间
│ │ │ ② gpt-4o       [默认]       812ms     99.2%  │ │   ← 回 ① 测整组、回 ② 测单个
│ ╰──────────────────────────────────────────────────╯ │
├──────────────────────────────────────────────────────┤
│ ● 数据来自真实调用的记录，不是此刻探测      模型控制台│   ← 脚：口径与用法
╰──────────────────────────────────────────────────────╯
```

- **序号是独立方块**，不写进名字里——名字被截断也不会吃掉序号；
- **状态靠「行底横向渐变」**表达（左端状态色 → 右端中性底）：正常极淡、降级琥珀、故障红、
  无数据灰。健康那档故意只掺 10%——异常的几行才该跳出来；
- 卡宽 1080（明细卡 1160），模型名普遍很长；
- 右上角角标写**这张卡的性质**（`只读` / `选单` / `详情` / `告警` / `完成` / `管理员`），
  **不写「实时」**：数字来自已发生的调用，不是此刻探测；
- **回执一律直发**（`event.send()`，不进 AstrBot 结果链）：卡片和文字都**不会 @ 发送者**，
  全局配置「回复时 @ 发送人」对本插件不生效；
- 字体找不到时**降级成纯文本**（序号与状态词照旧带上），不发豆腐块图。

**配色**：设置页选主题（`card_theme`），共八套——樱粉（默认）/ 靛蓝 / 紫罗兰 / 青碧 /
琥珀橙 / 落日橙 / 朱红 / 石墨灰。只影响聊天卡片、不影响 WebUI，改完下一条卡片就生效。
三张卡的颜色固定不跟随主题：**红 = 报错**（看日志）、**橙 = 告警 / 进度**（等或处理）、
**绿 = 恢复**（好消息）。

**字体**：查找顺序是 **`card_font_path` 指定路径 → `data/fonts/` 等投放目录 → 系统字体**
（Windows 微软雅黑 / Linux Noto Sans CJK / macOS 苹方）。插件**不打包中文字体**——
一份全量中文字体 3~25MB，而这个 zip 才 1MB，为「开箱有中文」让所有人多下几十 MB 不划算。

- **Docker / 没有中文字体的环境**：把字体文件丢进挂载卷的 `data/fonts/` 就行，
  不用填路径、不用重装插件。支持 `.ttc / .otf / .ttf / .woff2 / .woff`；
  目录里有多个时按 **霞鹜文楷 > 圆体 > Noto > 思源 > 苹方 > 雅黑** 挑，想指定某一份就填 `card_font_path`；
- 另一个可选位置是 `data/plugin_data/astrbot_plugin_model_panel/fonts/`（优先级更高，卸载时一起清）；
- **放下文件就生效，不用重启、也不用改配置**：探测只缓存成功结果，所以「先重启、
  之后才往挂载卷丢字体」这条最常见的路是通的；改完 `card_font_path` 点保存会立刻重探，
  属于锦上添花而不是必须。

## WebUI 面板

打开 AstrBot 面板里的「萌萌模型控制台」页：

- **首页总览**：模型数、默认模型、陪伴插件状态、调用次数（含 AstrBot 后台「提供商测试」
  与 WebChat）、今日 / 近 7 天预估花费；
- **模型管理**：按供应商分组一张表，同时管「参与哪些检测」（手动 / 定时 / 指令三通道独立）
  和「测一次看看活不活」；计费分类与单价（token 类按「每百万 token」填、最多 8 位小数，
  单列缓存命中价；按次类填每次多少钱）；**倍率与每日次数限制属于供应商分组**，组头一处填，
  个别模型用「倍率覆盖」例外；**预估花费 = 实际用量 × 单价 × 倍率**，
  估不出来显示「未填单价」而不是 ¥0.00；
- **插件模型**：扫描所有已安装插件的配置找模型项，单项换或批量「旧 → 新」；
- **实时监测**：每一次 LLM 调用都记台账（对话 / WebChat / 后台测试 / 探测），
  默认显示最新一次结果 + 窗口成功率；两本账分开记（核心 `provider_stats` 一轮一行、
  插件埋点一次一行），**有埋点时次数与最近一次以埋点为准**，不相加；
- **定时探测**：默认关，带四道成本护栏（每日预算硬闸、并发上限、付费模型重试为 0、
  撞手动检测让路）；
- **自动告警**：连续失败 → 发卡给管理员，带失败原因与错误分布、供应商级合并、冷却与恢复通知。

## 对外接口（给别的插件）

供 [萌萌权限控制台](https://github.com/windExplorer/astrbot_plugin_user_gateway) 的
「/切换模型检测」联动。**探测与统计口径只此一份**——别的插件不该自己再打一遍模型、
自己算成功率，否则同一个模型在两边的数字迟早对不上。

```python
md = context.get_registered_star("astrbot_plugin_model_panel")
panel = md.star_cls                      # 插件实例；未安装 / 被禁用时为 None

# ① 可用性 / 估时参数（不发请求）
info = panel.external_available()        # {probe_concurrency, probe_timeout, busy}

# ② 只读快照（不发请求、不花钱）
snap = await panel.external_snapshot(provider_ids=["..."], days=1.0)
# → {"ok": True, "items": {pid: {...}}, "missing": [...], "live_available": bool}

# ③ 真打一次（会消耗额度），结果写进本插件历史并喂进状态机 / 告警
res = await panel.external_detect(["..."])
# → {"ok": True, "results": [...], "items": {...}} / {"ok": False, "busy": True}
```

快照里单个模型的关键字段：

| 字段 | 含义 |
| --- | --- |
| `state` / `available` | `healthy` / `degraded` / `down` / `unknown`；`available` = 没被判成故障 |
| `latency_ms` | 最近一次调用的延迟（首字优先，与卡片同口径） |
| `avg_latency_ms` / `success_rate` / `samples` | 窗口内均值、成功率、样本数（没样本给 `None`，不编 100%） |
| `last_ts` | 最近一次**有数据**的时间（真实对话或探测都会更新） |
| `last_probe_ts` | 最近一次**探测**的时间——联动方做「同一模型几分钟内不重复测」按它算 |
| `last_error_code` / `reason` | 最近一次失败的错误码、状态判定原因 |

注意：`external_detect` 与其它探测共用一把全局锁，撞车返回 `busy=True`（不排队——
排队只会让两边一起超时），联动方据此提示稍后再试；外部发起的检测在历史里记为
`gateway`（面板显示「插件联动」），并且**联动方要自己控制频率**
（user_gateway 那边有指令冷却 + 模型探测冷却两道闸）。
