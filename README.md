# 🌸 萌萌模型控制台（astrbot_plugin_model_panel）

> ⚠️ ：本插件主要为我个人使用而开发，功能围绕自己的实际需求打磨，非通用产品。介意勿用，也欢迎 fork 自改。

## 初心

这个插件诞生的初衷其实很简单——**快速更换「我会永远陪着你」的模型**。

用 AstrBot 跑「我会永远陪着你」陪伴插件时，想换一个更聪明 / 更便宜的模型，总要去后台一个个改 provider 配置，麻烦又容易漏。于是做了这个面板：在 WebUI 里一键检测所有模型的延迟和存活、批量把旧模型替换成新模型，几秒钟搞定，不用碰后台。

> 本插件即为此配套而生。「我会永远陪着你」陪伴插件的官方地址：https://github.com/menglimi/astrbot_plugin_private_companion

## 功能

- **控制台总览**：LLM 模型数、默认模型状态、陪伴插件状态、最近一次检测存活率与累计统计
- **模型管理**（「模型检测」与「模型档案」已合成这一页）：按供应商分组、不分页，
  一张表同时管「这个模型参与哪几种检测」和「现在测一次看看活不活」。
  - 三通道各占一列并写清列名：**手动检测 / 定时巡检 / 指令检测**。它们回答的是三个
    不同问题——我手点的、系统自己花钱的、别人也能点的，所以不合并成一个开关
  - 组头可**一键设置本组计费类型**（下拉选完即作用到整组），以及**一键翻转本组某个通道**
    （芯片上写着 `4/5` 这样的当前参与数，点一下全开或全关）
  - 模型名**加粗**，第二行只放**备注**；供应商名已经在组头写过，行内不再重复
  - 延迟检测 + 存活检测，支持单测 / 全测 / 分组测；一键检测走「启动 + 轮询」异步任务，
    逐模型实时刷新，顶部给进度条与成功/失败计数
  - 错误归一化展示（成功/超时/失联/拒绝连接/鉴权失败/请求受限/模型不存在/服务异常/已跳过），
    每行有最近检测时间，「详情」弹窗看完整原始返回
  - 只有开了「手动检测」的模型才参与一键检测与分组测试
  - 计费分类：未标注 / 免费 / 限时免费（可填到期日）/ 试用额度 / 额度+超额付费 /
    按量付费 / 订阅内含；单价统一「每百万 token」并单列缓存命中价
  - 来源渠道（官方 / 聚合站 / 国内中转 / 自建本地）、角色定位（主力 / 备用 / 兜底 /
    专用 / 观察 / 弃用）、上下文窗口与 tool_call / 推理 / 流式能力，
    能读核心已有 models.dev 元数据的会预填，不用手抄
  - 定时巡检默认**只对不产生单次费用的计费类型开放**，付费模型要显式勾选；
    这一通道带「跟随默认」第三态（虚线框），改过就变显式设置
  - 改动先进草稿、底部「N 行未保存」再统一保存；**点检测时会自动先保存**，
    保证屏幕上开关的样子就是后端真正用的那份
- **默认模型**：展示 AstrBot 实际生效的默认模型（与运行时决议一致），并可设置默认对话模型、回退模型列表、图片转述模型
- **陪伴插件模型替换**：读取陪伴插件精准模型配置，一键批量替换主模型 / 备用模型
- **插件模型（全插件扫描）**：自动扫描**所有已安装插件**的配置，列出其中的模型项
  （schema 声明的模型选择项 / 值命中已加载模型 / 键名提示三级识别，逐条标注可信度），
  支持单项更换与「旧模型 → 新模型」批量替换；陪伴插件那种「顶层扁平副本 + 分组嵌套」
  的镜像配置会自动合并并同步写回。识别范围覆盖 AstrBot 全部 5 类 provider：
  对话 / 语音合成 / 语音识别 / 向量 / 重排序。
  插件 schema 里声明的**模型配置入口即使还没填值也会列出**（标「未配置」），
  可以直接在面板上给它选模型，不用再翻插件自己的配置页
- **实时监测**：把**每一次 LLM 调用**都记进台账——用户/群对话、WebUI 手动检测、
  指令检测、定时探测全都要，不只读对话。每行默认显示**最新一次调用结果**
  （判定 + 延迟 + 来源标签 + 错误码 + 时刻），另给窗口成功率。
  - 真实对话记录直接读 AstrBot 核心的 `provider_stats` 表，**不自己埋点、不额外花钱**
  - **成功率合并所有来源，延迟绝不跨来源合并**：探测是空载一句 PONG 的往返，
    和真实对话差一个数量级，平均到一起就没有意义。所以「平均首字」只统计对话、
    「探测延迟」单独一列
  - 按供应商分组铺满一页（不分页），组头带该组故障/降级/正常计数，
    组间按「最坏模型」排序 —— 出问题的供应商自动浮到最上面
  - 窗口内一次调用都没有时显示 `–` 而不是 100%；样本 n<3 时数值淡化
- **自动告警**：后台巡检判定连续失败 → 主动发卡片给管理员，带冷却、恢复通知、
  供应商级合并（一家挂 10 个模型发 1 条而不是 10 条）。
  告警文案统一脱敏（密钥 / Bearer 令牌 / URL 内凭据），投递失败会自动补发
- **定时探测**（默认关闭，需显式开启）：带四道成本护栏——每日调用预算硬闸、
  并发上限、付费类模型重试强制为 0、撞手动检测时让路顺延
- **历史存储**：每次检测记录持久化保存，跨重启保留，为后续历史记录 / 统计图预留
- **隐藏指令 `/陪伴分数`**：查询自己在陪伴插件里的好感度分数、关系阶段，
  以及**当前互动状态**（七档互动温度：回避 / 受伤 / 放松 / 活泼 / 温暖 / 亲近 / 爱意），
  并标注它是自动判定、管理员手动设置，还是按好感度推算的基线，以及是否有有效期

## 指令

全部指令都在聊天里发，群聊需要 @机器人（或按你配置的前缀唤醒）。

| 指令 | 权限 | 花额度 | 说明 |
| --- | --- | --- | --- |
| `/模型状态` | 全员 | ❌ | 模型健康与延迟总览卡片 |
| `/模型统计 <关键词>` | 全员 | ❌ | 单个模型明细卡片 |
| `/检测模型 <关键词…>` | **管理员** | ✅ | 真打一次模型，测存活与延迟 |
| `/模型静音 <名称> [时长]` | **管理员** | ❌ | 临时关掉某模型的告警推送 |
| `/陪伴分数` | 全员 | ❌ | 查陪伴插件好感度与互动状态 |

### `/模型状态`

不需要参数。输出一张浅色粉彩卡片：顶部是正常 / 降级 / 故障 / 无数据的汇总，
下面**列出全部已加载的对话模型**，每个一行：状态色条 + 模型名 + 最近一次延迟 + 窗口成功率。

- **不折叠行数**。这张卡的意义就是「一眼看完谁挂了」，截断会把恰好故障的那个藏起来；
  超过约 15 行自动折成两栏，不会长到没法扫读
- 模型名默认只写模型本身；只有**同名模型出现在多个渠道**时才带上供应商标，
  否则一长串「供应商/路径」在两栏里会被截得看不出差别
- 第二行只留给需要解释的话：故障原因、限时免费剩余天数、静音中、默认模型
- 排序是 **故障 > 降级 > 无数据 > 正常** —— 「没测过」比「已知正常」更该被看见
- 卡片脚注会写明延迟口径：对话取首字耗时、探测取整次往返，两者不可直接比较

纯读已有记录，**不请求模型、不产生任何费用**。

```
/模型状态
```

### `/模型统计 <关键词>`

按名称模糊匹配（供应商名、模型名、provider id 都算），输出明细卡片，
多一列首字 P95 和「失败次数 / 总次数」。

```
/模型统计 deepseek
/模型统计 硅基流动
```

匹配到 1~6 个出卡片；超过 6 个说明关键词太宽，会回列表提示你收窄。
同名模型在不同渠道各是一个独立 provider，所以这里可能一次命中多个，是符合预期的。

### `/检测模型 <关键词…>`

**管理员限定**，并且**会真实调用模型、产生额度消耗**。

```
/检测模型 kimi
/检测模型 硅基流动 deepseek
```

行为与限制：

- 只测**模型管理页里勾选了「指令检测」通道**的模型。没勾的会直接拒绝并告诉你去哪开
  ——这个通道单独存在，是因为指令在群里发、别人也可能触发，需要独立的准入名单
- 单次最多 **3** 个模型（正好 3 个放行）。超过就列出命中项让你收窄，不会静默只测前 3 个
- 先回一句「已开始检测」，后台跑完再把结果卡片发回原会话。
  3 个模型串起来最坏是 3 × 超时，直接在指令里等会让你以为 bot 挂了
- 与 WebUI 一键检测、定时巡检共用一把全局锁，撞车时礼貌拒绝
- 结果同样写进检测历史（来源标记为 `command`），所以实时监测的成功率里也算它

卡片里的延迟是**空载探测值**，脚注会写明它不等于真实对话延迟。

### `/模型静音 <名称> [时长]`

**管理员限定**。明知某个模型坏了且在等供应商修时，需要的是关掉噪音而不是删配置。

```
/模型静音 kimi 6h
/模型静音 硅基流动 30m
/模型静音 deepseek 1d
/模型静音 取消 kimi
```

- 时长支持 `30m` / `2h` / `1d`（纯数字按分钟算），不填默认 **2 小时**
- **只关通知，不影响状态采集与面板显示** —— 模型仍会被判成故障，只是不推消息
- 解除也可以直接等它自动到期，或传 `取消` / `解除` / `unmute`

### 前置条件：管理员 ID

`/检测模型`、`/模型静音` 以及所有告警投递，都依赖 AstrBot 的「管理员 ID」列表
（**WebUI → 平台配置 → 管理员 ID**，填真实 QQ 号）。

默认值 `astrbot` 是占位符不是真实账号，插件会主动跳过它。所以不填的话：
指令会被判定为无权限、告警一条也收不到（但不会丢，未送达的告警会保持待补发状态，
下一轮重试，超过 24 小时才放弃）。


## 安装

- **插件市场**：在 AstrBot 插件市场直接搜索「萌萌模型控制台」并安装
- **压缩包安装**：下载 Release 中的插件压缩包，在 AstrBot 插件管理页上传安装

安装后在 AstrBot 面板启用插件，打开「萌萌模型控制台」页面即可使用。
