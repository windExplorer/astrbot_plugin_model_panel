# 🌸 萌萌模型控制台（astrbot_plugin_model_panel）

> ⚠️ ：本插件主要为我个人使用而开发，功能围绕自己的实际需求打磨，非通用产品。介意勿用，也欢迎 fork 自改。

## 初心

这个插件诞生的初衷其实很简单——**快速更换「我会永远陪着你」的模型**。

用 AstrBot 跑「我会永远陪着你」陪伴插件时，想换一个更聪明 / 更便宜的模型，总要去后台一个个改 provider 配置，麻烦又容易漏。于是做了这个面板：在 WebUI 里一键检测所有模型的延迟和存活、批量把旧模型替换成新模型，几秒钟搞定，不用碰后台。

> 本插件即为此配套而生。「我会永远陪着你」陪伴插件的官方地址：https://github.com/menglimi/astrbot_plugin_private_companion

## 功能

- **控制台总览**：LLM 模型数、默认模型状态、陪伴插件状态、最近一次检测存活率与累计统计
- **模型管理**（「模型检测」与「模型档案」已合成这一页）：按供应商分组、不分页，
  一张表同时管「这个模型参与哪几种检测」和「现在测一次看看活不活」。
  - 三通道各占一列并写清列名：**手动检测 / 定时巡检 / 指令检测**。它们回答的是三个
    不同问题——我手点的、系统自己花钱的、别人也能点的，所以不合并成一个开关
  - 组头可**一键设置本组计费类型**（下拉选完即作用到整组），以及**一键翻转本组某个通道**
    （芯片上写着 `4/5` 这样的当前参与数，点一下全开或全关）
  - 模型名**加粗**，第二行只放**备注**；供应商名已经在组头写过，行内不再重复
  - 延迟检测 + 存活检测，支持单测 / 全测 / 分组测；一键检测走「启动 + 轮询」异步任务，
    逐模型实时刷新，顶部给进度条与成功/失败计数
  - 错误归一化展示（成功/超时/失联/拒绝连接/鉴权失败/请求受限/模型不存在/服务异常/已跳过），
    每行有最近检测时间，「详情」弹窗看完整原始返回
  - 只有开了「手动检测」的模型才参与一键检测与分组测试
  - 计费分类：未标注 / 免费 / 限时免费（可填到期日）/ 试用额度 / 额度+超额付费 /
    按量付费 / 订阅内含 / **按次计费**。token 类单价按「每百万 token」填并单列缓存命中价，
    按次类填「每次多少钱」——两种计价单位分开标，混填会差六个数量级
  - **倍率与每日次数限制属于供应商分组**，在组头一处填、整组模型都跟着走；
    个别模型要例外就在抽屉里填「倍率覆盖」，留空即跟随分组。生效倍率会在界面上回显
  - **预估花费**：`实际 token 用量 × 档案单价 × 倍率`（按次类用请求数）。
    首页给今日/近 7 天总额并说明「另有多少个模型未填单价」，模型行给各自金额。
    估不出来时显示 `未填单价` 而不是 `¥0.00` —— 后者会被读成「这模型真没花钱」
  - 每日次数限制**只展示不拦截**：组头显示 `421 / 500`，用到八成变橙、超了变红。
    注意这个次数只统计真实对话（不含定时探测与手动检测），所以它是供应商计数器的下限
  - 来源渠道（官方 / 聚合站 / 国内中转 / 自建本地）、角色定位（主力 / 备用 / 兜底 /
    专用 / 观察 / 弃用）、上下文窗口与 tool_call / 推理 / 流式能力，
    能读核心已有 models.dev 元数据的会预填，不用手抄
  - 定时巡检默认**只对不产生单次费用的计费类型开放**，付费模型要显式勾选；
    这一通道带「跟随默认」第三态（虚线框），改过就变显式设置
  - 改动先进草稿、底部「N 行未保存」再统一保存；**点检测时会自动先保存**，
    保证屏幕上开关的样子就是后端真正用的那份
- **默认模型**：展示 AstrBot 实际生效的默认模型（与运行时决议一致），并可设置默认对话模型、回退模型列表、图片转述模型
- **陪伴插件模型替换**：读取陪伴插件精准模型配置，一键批量替换主模型 / 备用模型
- **插件模型（全插件扫描）**：自动扫描**所有已安装插件**的配置，列出其中的模型项
  （schema 声明的模型选择项 / 值命中已加载模型 / 键名提示三级识别，逐条标注可信度），
  支持单项更换与「旧模型 → 新模型」批量替换；陪伴插件那种「顶层扁平副本 + 分组嵌套」
  的镜像配置会自动合并并同步写回。识别范围覆盖 AstrBot 全部 5 类 provider：
  对话 / 语音合成 / 语音识别 / 向量 / 重排序。
  插件 schema 里声明的**模型配置入口即使还没填值也会列出**（标「未配置」），
  可以直接在面板上给它选模型，不用再翻插件自己的配置页
- **实时监测**：把**每一次 LLM 调用**都记进台账——用户/群对话、WebUI 手动检测、
  指令检测、定时探测全都要，不只读对话。每行默认显示**最新一次调用结果**
  （判定 + 延迟 + 来源标签 + 错误码 + 时刻），另给窗口成功率。
  - **两本账分开记，谁也不替代谁**：
    1. 核心的 `provider_stats` —— **一轮对话一行**，且归属到那一轮**最终跑成功**的提供商。
       插件不写它，只读；
    2. 插件自己的**逐次埋点**（包装 provider 的 `text_chat` / `text_chat_stream`）——
       **一次尝试一行**，主模型挂了、被备用救回来，这里照样留下主模型那条失败。
    所以「成功率 100% 但逐次有失败」不是 bug，是备用起作用了；反过来只看核心表，
    会出现「日志里今天挂了五次、面板写着全绿」这种骗人的读数
  - 因此表格里 **`成功率` 与 `逐次成败` 是两列**，后者还带 `失败 N 次` 与最近一次错误码；
    `逐次延迟` 单独一列给平均整轮与平均首字
  - 探测走的是插件自己的调用，会被埋点**抑制**，不会既记进探测历史又记进逐次台账重复计数
  - **窗口默认「今天」**（本地零点到现在），另有近 1/3/7/30 天。看监测的人第一问题
    永远是「今天怎么样」，默认给 7 天会把今天的故障摊平掉
  - **成功率合并所有来源，延迟绝不跨来源合并**：探测是空载一句 PONG 的往返，
    和真实对话差一个数量级，平均到一起就没有意义。所以「平均首字」只统计对话、
    「探测延迟」单独一列
  - 按供应商分组铺满一页（不分页），组头带该组故障/降级/正常计数，
    组间按「最坏模型」排序 —— 出问题的供应商自动浮到最上面
  - 窗口内一次调用都没有时显示 `–` 而不是 100%；样本 n<3 时数值淡化
- **自动告警**：后台巡检判定连续失败 → 主动发卡片给管理员，带冷却、恢复通知、
  供应商级合并（一家挂 10 个模型发 1 条而不是 10 条）。
  **故障告警会带上失败原因**：错误码单独一列（`超时` / `鉴权失败` / `连接失败`…），
  原因一行写「连续失败 5 次｜超时×5 · Request timed out after 45s」，
  脚注再汇总整批的「错误分布」—— 收到的人不用翻日志就知道该先修哪一头。
  告警文案统一脱敏（密钥 / Bearer 令牌 / URL 内凭据），投递失败会自动补发
- **定时探测**（默认关闭，需显式开启）：带四道成本护栏——每日调用预算硬闸、
  并发上限、付费类模型重试强制为 0、撞手动检测时让路顺延
- **历史存储**：每次检测记录持久化保存，跨重启保留，为后续历史记录 / 统计图预留
- **隐藏指令 `/陪伴分数`**：查询自己在陪伴插件里的好感度分数、关系阶段，
  以及**当前互动状态**（七档互动温度：回避 / 受伤 / 放松 / 活泼 / 温暖 / 亲近 / 爱意），
  并标注它是自动判定、管理员手动设置，还是按好感度推算的基线，以及是否有有效期

## 指令

全部指令都在聊天里发，群聊需要 @机器人（或按你配置的前缀唤醒）。

| 指令 | 权限 | 花额度 | 说明 |
| --- | --- | --- | --- |
| `/模型状态` | **管理员** | ❌ | 通用总览卡：分组 + 序号 + 延迟 + 成功率，只读 |
| `/模型统计 [关键词]` | **管理员** | ❌ | 不带参数发总览卡（回序号看明细），带关键词直接出明细卡 |
| `/模型检测 [关键词…]` | **管理员** | ✅ | 不带参数发带序号的卡片（可多选、可选分组），带关键词直接测 |
| `/切换系统模型 [关键词]` | **管理员** | ❌ | 不带参数发带序号的卡片，回数字改 AstrBot 默认对话模型 |
| `/模型静音 [开\|关]` | **管理员** | ❌ | 全部模型告警推送的总开关 |
| `/陪伴分数` | 全员 | ❌ | 查陪伴插件好感度与互动状态 |

> `/模型检测` 的旧名 **`/检测模型` 仍然可用**（注册成了别名），老习惯不用改。

除 `/陪伴分数` 外都是管理员限定。其中 `/模型状态`、`/模型统计`、`/模型检测` 展示与操作的
都是「指令检测」通道那份名单（能看到的就该是能测的）；`/切换系统模型` 例外，
它列全部有效对话模型 —— 换哪个模型本来就是全量决策。

### 通用卡片：所有指令长一个样

v1.3.10 起四个指令共用同一张卡（`card_render.render_card`），骨架与
[萌萌权限控制台](https://github.com/windExplorer/astrbot_plugin_user_gateway) 的「切换模型」
一致：**渐变头 + 白底行块 + 浅色脚**三段拼接。

```
╭────────────────────────────────────────────────╮
│ 模型状态                                  ╭──╮ │   ← 头：渐变底、大字结论、汇总点
│ 12 个模型 · 正常 9 / 故障 2               │实时│ │
│ ● 正常 9   ● 降级 1   ● 故障 2   ● 无数据  │    │ │
├────────────────────────────────────────────────┤
│                            延迟        成功率  │   ← 列头与小格右对齐
│ ╭────────────────────────────────────────────╮ │
│ │ ① OpenAI · 3 个模型                        │ │   ← 分组行：描边序号 + 组名 + 计数
│ │ ╭────────────────────────────────────────╮ │ │
│ │ │ ② ● gpt-4o     [默认]     812ms   99.2%│ │ │   ← 实心序号 + 状态点 + 名称 + 数字
│ ╰────────────────────────────────────────────╯ │
├────────────────────────────────────────────────┤
│ ● 延迟为最近一次调用耗时 · 09-22 12:30  模型控制台│   ← 脚：怎么用、什么口径
╰────────────────────────────────────────────────╯
```

几条刻意为之的规矩：

- **序号是独立方块，不写进名字里**。旧版把序号写成 `3. gpt-4o`，模型名一长就被截掉，
  用户照着卡片回号时根本找不到那个 3。现在名字被截断也绝不会吃掉序号
- **分组行与模型行共用同一个数字空间**：`① OpenAI`、`② gpt-4o`、`③ gpt-4o-mini`、
  `④ 硅基流动`… 回 `①` 就是「整组」，回 `②` 就是那一个模型，不用先分辨这个号是组还是模型
- **一律按名字排序**（供应商名、模型名各自升序）。旧版按「组内最坏状态」把故障的浮到最上面，
  看着聪明，但每次刷新顺序都可能变，而这张卡现在是要「照着一个号回数字」的入口
- 分组行用**描边**序号、模型行用**实心**序号，不靠颜色也能区分
- 状态色只出现在两处：行首的状态点、头部的汇总点。一行塞三个彩色胶囊就显廉价
- **不折栏**：窄栏里模型名会被截得看不出差别，两栏还得来回扫
- 延迟**一律按毫秒原样给**（`4200ms` 而不是 `4.2s`）—— 要比的正是那几百毫秒；
  只有超过 1 分钟才折成 `1分5秒`
- 错误说人话（`超时` / `请求受限` / `拒绝连接`），不把 `rate_limit` 这种内部码印到图上
- 字体找不到时**降级成纯文本**（序号与状态词照旧带上），而不是发一张豆腐块图

### `/模型状态`

不需要参数（**管理员限定**）。就是上面那张通用卡片：按供应商分组、带序号、
每行「状态色点 + 模型名 + 最近一次延迟 + 成功率」。

- 第二行只留给需要解释的话：失败次数、故障原因、限时免费剩余天数、告警静音中
- 「默认模型」做成名字右侧的胶囊标签，一眼就能找到当前走的是哪一个
- 展示范围与「指令检测」通道一致，一个都没开时会直接告诉你去哪勾
- 只读已有记录，**不请求模型、不产生任何费用**，也**不挂选单**（纯看）

```
/模型状态
```

### `/模型统计 [关键词]`

**管理员限定**，只读。

```
/模型统计            # 不带参数：发总览卡并挂上选单，回数字看那个模型的明细
/模型统计 kimi       # 带关键词：直接出明细卡，省一步
```

- 回序号后的**明细卡**多几列：首字、首字 P95、整轮、成功率、失败次数 / 总次数
- 可查范围同样是「指令检测」通道开放的模型；关键词匹配供应商名、模型名和 provider id
- 匹配到 1~6 个出卡片；超过 6 个说明关键词太宽，会提示你收窄
- 同名模型在不同渠道各是一个独立 provider，所以一次命中多个是符合预期的

### `/模型检测 [关键词…]`

**管理员限定**，并且**会真实调用模型、产生额度消耗**。

```
/模型检测                   # 不带参数：发带序号的卡片，回数字（可多选）即检测
/模型检测 2 4               # 也可以一次点两个（多选）
/模型检测 1                 # 回分组序号 = 测整组
/模型检测 kimi              # 带关键词：直接测，单次最多 3 个
```

**不带参数时给的还是那张通用卡片**（模型名记不住，是这条指令最常见的卡点）：

- 列出范围 = 开放了「指令检测」通道的全部模型，序号就是卡片上那个数字
- **回序号即开始检测，可以多选**：`2`、`2 4`、`1,3` 都认（分隔符支持空格 / 逗号 / 顿号），
  一条消息最多 8 个序号；**回分组序号就测整组**
- 一次最多真打 **10** 个模型（多选的上限，分组可能很大），超了会让你少选几个
- 选单 **3 分钟有效、取一次即作废**（同一串数字不会被执行两遍）；越界不执行也不作废，可重输
- 认序号只认「整条消息只有数字和分隔符」：发 `3楼见`、发长文都不受影响，
  而且**只有列出选单的那个人**回数字才算数 —— 群里另一个人回 `3` 不会替他执行

带关键词时的行为：

- 只测**模型管理页里勾选了「指令检测」通道**的模型。没勾的会直接拒绝并告诉你去哪开
  ——这个通道单独存在，是因为指令在群里发、别人也可能触发，需要独立的准入名单
- 单次最多 **3** 个模型（正好 3 个放行）。超过就列出命中项让你收窄，不会静默只测前 3 个
- 先回一句「已开始检测」，后台跑完再把**结果卡片**发回原会话。
  多选几个模型串起来最坏是 N × 超时，直接在指令里等会让你以为 bot 挂了
- 与 WebUI 一键检测、定时巡检共用一把全局锁，撞车时礼貌拒绝
- 结果同样写进检测历史（来源标记为 `command`），所以实时监测的成功率里也算它

结果卡里的延迟是**空载探测值**（脚注会写明它不等于真实对话延迟），每行带各自的检测时刻。

### `/切换系统模型 [关键词]`

**管理员限定**，**不调用模型、不花钱**。改的是 AstrBot 的默认对话模型
（主配置里 `providers[?].model_names[0]` 那个默认项），等价于去后台配置里手点，
只是不用离开聊天窗口。

```
/切换系统模型                # 发带序号的卡片，回数字即切换
/切换系统模型 kimi           # 直接按关键词切：命中唯一才动，多个则让你收窄
/切换系统模型 取消           # 关掉挂着的选单
```

- 列表 = 当前加载出来的**全部有效对话模型**（不按检测通道过滤）
- 每行附**今天的状态与延迟**（与面板同一套口径），当前默认那行带「默认」胶囊并高亮
- 序号选单的规则与 `/模型检测` 一致：整条消息是序号才算、只认列出选单的那个人、
  3 分钟有效、取一次即作废、越界可重输；**切换是单选的**（回多个数字会被提示只回一个）
- 切换成功回显「旧 → 新」，并同步刷新运行时里的默认项，下一条对话就走新模型
- 任何一步失败（读不到主配置、没有可写的默认字段、保存抛错、序号对应的模型已被删）
  都会把原因回给你并**放弃改动**，不会出现「配置改了一半」

### `/模型静音 [开|关]`

**管理员限定**。这是**全部模型告警推送的总开关**，不是针对某一个模型
（v1.3.10 起改的口径：被多家供应商的告警一起刷屏时，真正想按的是总闸）。

```
/模型静音            # 切换：当前开着就关掉，当前关着就打开
/模型静音 关         # 明确关掉
/模型静音 开         # 明确打开
/模型静音 状态       # 只看当前状态
```

- 关掉之后**所有**模型的告警都不再推送，**连待补发的历史告警也一并停掉**
  （否则按了静音仍然被刷屏，等于没静音）
- **只静音通知，不影响状态采集与面板显示** —— 模型照常被判成故障、面板照常标红
- 开关落在插件配置 `alert_notify_enabled` 上（WebUI 配置里「把告警主动发给管理员」那一项），
  所以指令与 WebUI 互相看得见，重启也不会丢；保存失败会**回滚**并告诉你原因

### 前置条件：管理员 ID

`/模型状态`、`/模型统计`、`/模型检测`、`/切换系统模型`、`/模型静音` 以及所有告警投递，
都依赖 AstrBot 的「管理员 ID」列表（**WebUI → 平台配置 → 管理员 ID**，填真实 QQ 号）。

默认值 `astrbot` 是占位符不是真实账号，插件会主动跳过它。所以不填的话：
指令会被判定为无权限、告警一条也收不到（但不会丢，未送达的告警会保持待补发状态，
下一轮重试，超过 24 小时才放弃）。


## 安装

- **插件市场**：在 AstrBot 插件市场直接搜索「萌萌模型控制台」并安装
- **压缩包安装**：下载 Release 中的插件压缩包，在 AstrBot 插件管理页上传安装

安装后在 AstrBot 面板启用插件，打开「萌萌模型控制台」页面即可使用。
